DOMAIN MONITOR — INSTALLATION & OPERATING GUIDE
================================================

WHAT IS INCLUDED
----------------
- index.php: the complete single-file application (HTML, CSS, JavaScript and PHP).
- config.php: server-side TryAPI key and application settings.
- .htaccess: /monitor/domain.tld permalink routing and basic config protection.
- storage/: JSON records, IANA RDAP cache and rate-limit files are written here.

REQUIREMENTS
------------
- PHP 8.0 or newer (PHP 8.2/8.3 recommended).
- Apache with mod_rewrite and AllowOverride enabled for pretty /monitor/domain.tld URLs.
- PHP OpenSSL enabled and outbound SMTP connections allowed by the hosting plan.
- Outbound HTTPS access. cURL is recommended; PHP URL fopen is used as a fallback.
- The PHP process must be able to write to storage/ and its subfolders.
- Optional PHP extensions: mbstring and intl (used for improved IDN handling).

INSTALLATION
------------
1. Upload the ZIP contents into the target website's document root (usually public_html).
2. Edit config.php:
   - Set APP_BASE_URL to the canonical website URL, e.g. https://monitor.example.com
     (no trailing slash). This is strongly recommended for correct email links.
   - APP_FROM_EMAIL is preconfigured as connect@atreyagroup.in. It must match the authenticated SMTP mailbox.
   - SMTP_HOST is smtp.hostinger.com, SMTP_PORT is 465 and SMTP_ENCRYPTION is ssl.
   - SMTP_USERNAME and SMTP_PASSWORD are prefilled with the mailbox credentials supplied for this build.
   - Keep config.php private. If you rotate the mailbox password, update SMTP_PASSWORD here.
   - TRYAPI_KEY is prefilled with the key supplied for this build. Keep it private.
3. Ensure storage/ and its subfolders are writable by PHP. Start with 0750; use your host's
   file manager to adjust ownership/permissions if needed. Avoid 0777 unless the host
   explicitly requires it as a temporary diagnostic step.
4. Confirm Apache allows .htaccess overrides and mod_rewrite is enabled.
5. Visit the website homepage and submit a test domain/email address.
6. Verify the email. Monitoring starts only after the recipient confirms ownership.

PERMALINKS
----------
A domain receives one deterministic JSON file based on SHA-256 of its normalised name.
The public page is generated by the same index.php file, for example:
https://monitor.example.com/monitor/bagchi.net

If pretty URLs do not work, check mod_rewrite and AllowOverride. As a temporary alternative,
use the query route: index.php?route=monitor&domain=bagchi.net

HOW DUPLICATE DOMAINS WORK
-------------------------
- Domain names are normalised (lowercase, URL scheme/path and leading www removed).
- One JSON file is created for each unique normalised domain.
- Different visitors are stored as subscriber entries inside that domain's JSON file.
- A repeat submission by the same email updates that subscriber's interval rather than adding
  another subscriber.
- Subscriber email addresses are never printed on the public monitoring page.

MONITORING MODEL — IMPORTANT
----------------------------
This ZIP implements visitor-triggered monitoring (Plan B). The PHP monitoring engine runs
when a web request reaches index.php. It processes up to MAX_CHECKS_PER_REQUEST due domains
per request to avoid making one page load wait for every overdue domain.

If the site receives no requests for 7 days, 24 hours, or longer, no checks or emails execute
while it is idle. When a visitor returns, overdue records are checked using their current
status; missed historical intervals are NOT replayed. The next target check is scheduled from
the time of that catch-up lookup. This is not guaranteed 15-minute background monitoring.

TryAPI's domain availability endpoint is queried from PHP. RDAP is queried separately through
the IANA bootstrap directory to enrich the public registration information. RDAP can be
unsupported for some TLDs, delayed, limited or privacy-redacted. A 404 RDAP response by itself
is not treated as proof of normal registrability.

API USAGE & LIMITS
------------------
- Endpoint: https://tryapi.dev/api/v1/domain/availability?domain=example.com
- Authentication: Authorization: Bearer YOUR_API_KEY
- TryAPI documents the availability endpoint as free per call with a 60/minute endpoint limit.
- Its help centre currently describes 1,000 introductory free calls for new accounts. Verify
  the current account allowance and any balance/billing state in your TryAPI dashboard.
- TryAPI caches its availability result for 10 minutes, according to its endpoint documentation.
- This application does not expose the API key to browser JavaScript.

EMAIL
-----
- This build sends through authenticated Hostinger SMTP; it no longer uses PHP mail().
- SMTP host: smtp.hostinger.com
- Recommended connection: port 465 with implicit SSL/TLS.
- Alternative connection: port 587 with STARTTLS. To switch, set SMTP_PORT to 587 and SMTP_ENCRYPTION to 'tls' in config.php.
- SMTP username: the complete mailbox address, connect@atreyagroup.in.
- SMTP password: the mailbox password configured in config.php. This is not the Hostinger hPanel login password.
- Sender address: APP_FROM_EMAIL, which should match the authenticated SMTP mailbox.
- Hostinger's official settings: https://support.hostinger.com/en/articles/1575756-how-to-get-email-account-configuration-details-for-hostinger-email

New subscriptions receive an email verification link. Status notifications are sent at each subscriber's configured interval after the verification time, including when the status has not changed. The public dashboard counts messages accepted by Hostinger SMTP, not confirmed inbox deliveries. SMTP acceptance does not guarantee inbox placement. Subscribers can unsubscribe using their private link included in notification emails.

If SMTP sending fails, check the PHP error log for a diagnostic identifying the failed SMTP stage and server response. Do not share config.php or SMTP error logs publicly. Confirm that the mailbox exists, can log in to Hostinger Webmail, and that outbound SMTP access is allowed by the hosting plan.

DOMAIN LIFECYCLE TIMELINE
------------------------
The public /monitor/domain.tld page now includes a lifecycle timeline with:
- RDAP registration date, published expiration date, last-changed date and today's marker.
- Current lifecycle stage inferred from the returned RDAP/EPP statuses.
- Projected registrar-grace, redemption, pending-delete and estimated release milestones.
- Watch this domain, Copy link and Copy all actions in the domain header.

Projection caveat:
- For .com and .net, the page can show an illustrative outer-bound scenario using 45 days
  after expiry for registrar auto-renew grace, then 30 days for redemption and 5 days for
  pending delete. This is NOT a guaranteed release date. ICANN policy allows registrars to
  delete expired registrations at any time after expiry; the redemption period begins after
  registry deletion. A domain can therefore drop earlier than the displayed scenario.
- For other TLDs, fixed calendar projections are withheld because registry/registrar rules
  differ. The page shows the lifecycle sequence and explanatory durations without inventing
  a date.
- Actual RDAP/EPP statuses take precedence over all projected dates. A Pending Delete or
  Redemption status is a registry-reported status; dates shown in the forecast are estimates.
- A public RDAP record does not guarantee normal registration will be possible at drop time.
  Registry reservation, premium-name, auction, backorder and registrar handling may apply.

Reference policies:
- ICANN Expired Registration Recovery Policy: https://www.icann.org/en/contracted-parties/consensus-policies/expired-registration-recovery-policy/expired-registration-recovery-policy-21-02-2024-en
- ICANN EPP Status Codes: https://www.icann.org/resources/pages/epp-status-codes-2014-06-16-en
- IANA RDAP JSON values: https://www.iana.org/assignments/rdap-json-values

STATUS HANDLING
---------------
- TryAPI availability=true is displayed as Available / Unregistered (subject to registry,
  reserved-name, premium-name and registration-provider restrictions).
- RDAP object found is displayed as Registered, with recognised EPP statuses mapped to
  lifecycle labels such as Grace Period, Redemption Period, Pending Delete, Hold and Transfer Lock.
- If RDAP returns 404 but TryAPI cannot confirm availability, the dashboard says availability
  is unconfirmed. It does not mark the domain available from a 404 alone.
- Monitoring automatically stops when TryAPI positively reports available=true. Change
  STOP_ON_AVAILABLE in config.php to false if monitoring should continue after availability.

SECURITY & PRIVACY
------------------
- Keep config.php private. Apache .htaccess rules deny direct requests to config.php.
- storage/ is denied to public web requests by its own .htaccess file.
- If you use Nginx or another server that ignores .htaccess, add equivalent deny rules for
  /storage/ and /config.php, or move config.php and storage outside the document root and
  update STORAGE_PATH in config.php.
- Do not publish the ZIP or config.php in a public repository.
- The public RDAP JSON view redacts email, telephone and postal-address fields. Public
  registration data availability depends on registry policy.
- Add a privacy notice and terms appropriate to your jurisdiction before public launch.
- The app includes a basic per-IP form rate limit and a honeypot field; it is not a full
  anti-abuse or DDoS protection system.

TROUBLESHOOTING
---------------
1. “TryAPI returned HTTP 401”: verify the API key in config.php.
2. HTTP 402: the TryAPI account may have exhausted its available credits/allowance.
3. HTTP 429: endpoint rate limit reached; wait and retry. Do not increase the request volume.
4. No verification email: check the PHP error log for the SMTP stage and server response. Confirm the mailbox password, SMTP host, port and encryption. Check spam and SPF/DKIM/DMARC alignment.
5. “Storage directory is not writable”: correct storage folder ownership/permissions.
6. /monitor/domain.tld returns 404: enable Apache mod_rewrite and AllowOverride, or use the
   query-string permalink alternative.
7. Full RDAP fields are missing: not every TLD publishes every field or offers an RDAP service.

IMPORTANT CREDENTIALS NOTE
--------------------------
The Hostinger SMTP mailbox username and password are stored in config.php. Treat config.php as a secret, restrict access to it and rotate the mailbox password if it has been exposed. Update SMTP_PASSWORD after any password change. Never put SMTP credentials in JavaScript or publish this ZIP in a public repository.

IMPORTANT API KEY NOTE
---------------------
The TryAPI key was inserted into config.php as supplied for this build. Treat API keys as
secrets. If the key has been shared outside a trusted/private environment, rotate it in TryAPI
and replace TRYAPI_KEY in config.php.
